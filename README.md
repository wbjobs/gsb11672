# IndexedDB 批量写入与配额管理

纯原生 Web 技术(无框架)演示:向 IndexedDB 批量写入大量数据,监控存储配额,并在异常链路上提供完整的降级、重试与恢复能力。

## 运行

需要通过 HTTP 服务访问(ES Module 与 Worker 不支持 file://):

```bash
python3 -m http.server 8080
# 打开 http://localhost:8080
```

## 功能

- **批量写入**: Web Worker 生成数据(确定性伪随机 payload + CRC32),主线程事务批量提交,背压控制
- **配额监控**: StorageManager `estimate()` 轮询,Canvas 环形图可视化,支持 `persist()` 持久化请求
- **写入进度**: 按已提交记录数精确计算,实时进度条与统计卡片
- **操作**: 暂停/继续、重试失败批次、校验完整性、手动 LRU 清理、清空、重置数据库

## 异常链路

| 场景 | 策略 |
| --- | --- |
| 配额不足 | 先 LRU 清理最旧 10% 记录并重试;仍不足则降级到内存存储 |
| 写入失败 | 指数退避重试 3 次,仍失败进入失败队列,可手动重试 |
| 事务中断 | checkpoint 与数据同事务提交,刷新后可从断点恢复 |
| 数据损坏 | 每条记录 CRC32 校验,一键扫描 IDB + 内存两侧 |
| 降级一致性 | 内存与 IDB 共用同一记录格式与序号空间,统计/校验/清空合并处理 |
| 隐私模式 | IndexedDB 不可用或 StorageManager 缺失时自动纯内存运行,不崩溃 |
| 数据库被删 | 连接异常时自动重开,重开失败则降级内存 |

界面内置故障注入(随机中断事务、模拟配额不足、篡改记录)用于演示上述链路。
